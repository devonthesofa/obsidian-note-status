# Pla de correcció del Scorecard de Note Status

La branca `fix/105/scorecard-issues` cobreix la [incidència #105](https://github.com/devonthesofa/obsidian-note-status/issues/105). El [Scorecard de la versió 3.1.2](https://community.obsidian.md/plugins/note-status#scorecard) mostra **Review: Caution**, amb **125 avisos** i **4 observacions**. La revisió també indica que l'escaneig de malware no està disponible. L'objectiu és corregir els avisos, acreditar la procedència dels fitxers de release i validar els fluxos del plugin abans de publicar.

## Fase 0. Establir la línia base

- [x] Registrar els avisos del Scorecard per regla i fitxer a l’[inventari de la versió 3.1.2](#inventari-davisos-de-la-versió-312).
- [x] Instal·lar amb `pnpm install --frozen-lockfile`. La compilació i el lint existent passen. Prettier ja marcava `README.md`, `templates/digital-garden-workflow.json` i `types/pluginSettings.ts`. El build també regenera l'índex de plantilles amb diferències respecte del fitxer versionat.
- [x] Executar el linter oficial en mode informatiu amb ESLint 9, TypeScript 5 i `typescript-eslint` 8 fora del repositori. Reprodueix, entre d'altres, les 20 promeses sense gestionar, les 8 promeses en contextos incompatibles i els 5 camps del manifest. El projecte encara usa ESLint 8 i TypeScript 4.7. [Requisits del linter oficial d'Obsidian](https://github.com/obsidianmd/eslint-plugin/blob/master/package.json)
- [x] Preparar un vault local a `/tmp/note-status-scorecard-vault` amb notes que guarden un estat únic o una llista, una nota sense estat, un adjunt amb estat, una plantilla i els fitxers de sincronització.

**Tancament.** Tenim un inventari d'avisos i uns resultats locals que es poden repetir.

- [x] Validar Obsidian `1.7.4`, primera versió pública de la sèrie 1.7. El vault de prova confirma la càrrega del plugin i els estils, l'escriptura de frontmatter i l'obertura de la vista agrupada i el dashboard. [Publicació d'Obsidian 1.7](https://obsidian.md/changelog/2024-10-16-desktop-v1.7.4/)
- [x] Fixar `minAppVersion` a `1.7.4` per a la futura versió `3.1.3` i afegir-la a `versions.json` amb el mínim. Registrar també el mínim que declarava la release anterior.

**Tancament.** El linter valida el manifest i el plugin funciona en la versió mínima amb les vistes i l'escriptura de frontmatter.

**Abast.** 20 promeses sense gestionar i 8 callbacks, propietats o mètodes amb un retorn incompatible.

- [x] Gestionar el resultat de la inicialització i de les operacions `revealLeaf`, `openFile` i `setViewState`. Esperar cada operació quan el flux en depengui i tractar els errors dels fluxos que s'executin en segon pla.
- [x] Revisar el selector d'estat, el proveïdor de dades agrupades, el dashboard, la barra d'estat, les comandes i la sincronització. Fer servir callbacks síncrons amb gestió explícita de rebuig quan React o Obsidian esperin un retorn `void`.
- [x] Donar resposta a les operacions fallides de lectura o escriptura del porta-retalls, importació i exportació. La prova amb un JSON invàlid mostra el motiu de la fallada i l'exportació correcta genera el fitxer esperat.
- [x] Fer síncron `onunload`. Les proves a Obsidian 1.7.4 confirmen que es cancel·len els temporitzadors pendents quan es desactiva el plugin i que una nota creada amb una plantilla conserva l'estat que ja tenia.

**Tancament.** Els avisos de promeses es resolen al linter. Les proves cobreixen inici, desactivació, obertura de vistes, sincronització fallida i creació de notes amb plantilla.

- [x] Substituir les propietats de subratllat assenyalades per una línia interior que conserva el color configurable. Comprovar-ne l'estil calculat al nom d'un fitxer de l'explorador.
- [x] Moure l'estil estàtic de la barra d'estat a una classe CSS i regenerar `styles.css`. La compilació i la comprovació de l'estil calculat passen.

**Tancament.** Els avisos de CSS es comproven sobre els fitxers font i l'artefacte compilat. Els controls i l'explorador es veuen correctament amb els temes clar i fosc.

- [x] Afegir `CONTRIBUTING.md` amb la instal·lació, les comprovacions i el procés existent per contribuir plantilles.

**Tancament.** Passen la compilació, els linters i el pre-commit amb les dependències actualitzades.

- [x] Configurar la creació de l'esborrany amb els mateixos fitxers acreditats. El workflow comprova que el tag coincideix amb la versió del manifest. La prova de `pnpm version` confirma que el tag es genera sense el prefix `v`.
- [ ] Verificar la primera execució a GitHub Actions. El workflow descarrega `main.js`, `styles.css` i `manifest.json`, els compara amb els fitxers de la compilació i executa `gh attestation verify`. Completar les proves funcionals abans de crear el tag de la release. Fer la comprovació pública després de publicar-la.

- [ ] Provar escriptura de frontmatter en llista i valor únic, mapatges de claus, estats d'adjunts, canvis massius i reanomenament i eliminació de fitxers.
- [ ] Provar instal·lació i actualització des de 3.1.2 amb dades existents. Fer les comprovacions en escriptori a la versió mínima i en una versió actual, i provar els fluxos disponibles a mòbil.
- [ ] Verificar que el porta-retalls es fa servir a partir d'accions explícites i que l'enumeració del vault es correspon amb les funcions que la necessiten. Són les altres dues observacions del Scorecard i corresponen a capacitats del plugin. La disponibilitat de l'escaneig de malware depèn d'Obsidian.

**Tancament.** Les proves del plugin passen i el Scorecard de la nova release reflecteix les correccions i les attestations.
